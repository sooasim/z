# 다국어 (i18n) / Languages

JETPOOL 웹은 **한국어 · English · 日本語 · 简体中文 · Tiếng Việt** 5개 언어로 동작합니다.
한국어가 원본(source) 언어이고, **영어가 다른 모든 언어의 폴백(pivot)** 입니다.

## 언어가 결정되는 순서

1. 사용자가 명시적으로 고른 값 — `jp_lang` 쿠키, 없으면 `localStorage.jp_lang`
2. 브라우저 언어 — `navigator.languages` 를 **primary subtag** 로 매칭 (`en-GB` → `en`, `zh-Hant-TW` → `zh`)
3. 지원 언어가 하나도 없으면 한국어

`apps/web/lib/i18n.tsx` 가 이 판정을 **마운트 이후에** 수행합니다. 정적 export(`gh-pages` 데모)에는 서버가
없고 HTML은 항상 한국어로 프리렌더되므로, 하이드레이션 불일치를 피하려면 브라우저 조회가 렌더 중이 아니라
`useEffect` 안에서 일어나야 합니다. 언어가 정해지면 `<html lang>` 이 해당 BCP-47 태그로 갱신됩니다.

헤더의 지구본 메뉴와 `/account/preferences` 에서 언어를 고를 수 있고, **"브라우저 언어 사용"** 을 고르면
명시적 선택이 지워져 다시 1→2 순서를 따릅니다.

## 번역이 들어가는 곳 세 군데

| 대상 | 파일 | 키 |
|---|---|---|
| 화면 공통 크롬(내비게이션·상태·공통 동사) | `apps/web/lib/dict.ts` | `t('nav.stay')` 처럼 **기호 키** |
| 화면별 문구 | `apps/web/lib/phrases.ts` | **영문 원문 자체** (gettext 의 msgid 방식) |
| 숫자·금액·날짜 | `apps/web/lib/format.ts` | `Intl` + 언어별 BCP-47 태그 |

화면 문구는 약 2,500곳에서 `L('검색', 'Search')` 형태로 인라인 작성돼 있습니다. 호출부를 5개 언어 구조로
바꾸는 대신, `L` 은 인자를 2개로 유지하고 **영문 쪽을 `phrases.ts` 에서 조회**합니다. 덕분에 번역을 추가할 때
화면 코드를 건드릴 필요가 없습니다. 테이블에 없는 문구는 **영어로 표시**되며, 이것이 문서화된 폴백입니다.

같은 조회 경로를 상태 라벨(`statuses.ts`)·enum 라벨(`enums.ts`)·`{ko, en}` 복사 테이블(`pickText`)이
공유하므로, 문구 하나를 `phrases.ts` 에 넣으면 그 문구가 쓰이는 모든 지점이 함께 번역됩니다.

### 현재 커버리지

- **완전 번역**: 내비게이션, 페이지 상태, 공통 동사, 반복 UI 어휘 약 180개(표 머리글·필드 라벨·버튼),
  상태 배지, 국가명·언어명(`Intl.DisplayNames`), 금액·날짜·숙박일수 형식
- **영어 폴백**: 장문 마케팅 카피(홈 브랜드 블록, 전세기 소개 등), 보간이 들어간 문장
  (`게스트 취소 (환불 50%)` 같은 패턴 라벨), API 가 돌려주는 자유 텍스트

## 번역 추가하기

`apps/web/lib/phrases.ts` 의 해당 언어 테이블에 `'<영문 원문>': '<번역>'` 을 넣기만 하면 됩니다.
키는 `L(...)` 의 두 번째 인자와 **공백·생략부호까지 똑같아야** 합니다.

`apps/web/test/i18n.test.ts` 가 다음을 강제합니다.

- `dict.ts` 의 모든 키가 5개 언어에 **빠짐없이** 존재 (타입에서도 `Record<DictKey, string>` 로 강제)
- `phrases.ts` 의 세 언어가 **동일한 키 집합**을 가짐
- 번역이 비어 있지 않고, 영문과 똑같은 값은 `SAME_AS_ENGLISH` 에 선언된 차용어뿐
- `phrases.ts` 의 키가 **실제로 화면에서 쓰이는 문구**임 — 쓰이지 않는 키가 남으면 실패하므로 테이블이
  조용히 썩지 않습니다
- 모든 언어에서 상태 배지가 원시 enum(`SOME_UNKNOWN_STATE`)을 노출하지 않음

## 언어 추가하기

1. `apps/web/lib/langs.ts` 의 `LANGS` 에 `{ code, locale, endonym, english }` 추가
2. `apps/web/lib/format.ts` 의 `Lang` 유니온과 `LOCALE` 맵에 추가 (필요하면 `nightsText`·`CJK` 도)
3. `apps/web/lib/dict.ts` 에 `Record<DictKey, string>` 추가 — **타입체크가 누락 키를 잡아줍니다**
4. `apps/web/lib/phrases.ts` 의 `PHRASES`·`SAME_AS_ENGLISH` 에 테이블 추가
5. `pnpm --filter @jetpool/web test` — 위 검증이 전부 돌아갑니다

## API 쪽

API 는 `users.locale` 을 저장하고 CMS 콘텐츠를 `locale` 별로 보관합니다(기본 폴백 `ko-KR`).
현재 CMS 에는 `ko-KR`/`en` 항목만 있어, 그 밖의 UI 언어에서는 홈의 원격 콘텐츠 블록이 영어 항목으로
떨어집니다(`apps/web/app/view.tsx`). CMS 에 해당 로케일 항목을 넣으면 자동으로 사용됩니다.
